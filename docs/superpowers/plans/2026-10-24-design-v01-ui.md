# UI 改版（可爱清新视觉方案 v0.1）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 ardot 设计文件「可爱清新视觉方案 v0.1」把桌宠的右键菜单、设置窗口（对话记录+形象管理）、气泡与输入条对齐到新视觉规范，形象管理页落成可用功能。

**Architecture:** 纯渲染层 UI 改版 + 一处 Go 小改（形象探测返回体积/表情数，供形象管理页元信息）。高度自适应菜单用纯函数 `menuHeight(n)` 作单一事实来源（usePetMenu 扩展量与 PetMenu 渲染高度同源，杜绝「窗口底部留白拦截鼠标」陷阱）；设置窗口侧栏拆成壳 + 两页（对话记录/形象管理）；形象导入/删除从菜单收敛到设置·形象管理页，并新增 `models-changed` IPC 广播做跨窗同步（沿用 chat-cleared 模式）。

**Tech Stack:** Electron 44 + React 18 + zustand + PIXI v7 + Tailwind v4（JSX 只写工具类）；Go + gin（assets 探测）；vitest + @testing-library/react；Go test。

**Spec:** ardot 设计文件「可爱清新视觉方案 v0.1」（`cocraft://localhost/file/739813504834201`，01 气泡/02 输入/03 设置·对话记录/05 形象管理/07 右键菜单——本计划已提取全部实测值，直接以本文档数值为准）；`docs/design-v1/README.md`（04 状态与规范仍有效）；`docs/design.md`（v2 产品规格）。06 模型与连接不在此计划（见「关键决策」）。

## Global Constraints

- **显示名**：产品显示名 AI桌宠；用户可见文案禁用具体角色名（天依/洛天依）；测试夹具用中性素材名（haru/shizuku）。
- **气泡铁律**：气泡 `pointer-events-none` 必须保留（点击穿到桌面）；ChatPanel 打开时 SpeechBubble 隐藏（App 互斥控制，勿破坏）。
- **菜单高度铁律**：菜单高度单一事实来源 `menuHeight(n)`——usePetMenu 的扩展量与 PetMenu 的渲染高度必须引用同一函数（图 07 设计注释原话：高度必须跟着改，MENU_H 与 MENU_REQUIRED_H 要同步）。
- **定位铁律**：气泡/菜单定位只走 `live2d/windowGeometry` 几何 store 渲染期推导，组件不得自行监听 resize 定位（监听顺序竞态）。
- **穿透状态机**：usePassthrough 的 effect cleanup 无条件置穿透 true；新 effect 的立即同步必须无条件发 IPC（走本地去重会被跳过 → 窗口卡死穿透）。
- **样式**：JSX 只写 Tailwind 工具类（token 引用 `bg-primary`、`gap-(--sp-1)`，无 token 的裸值用默认刻度/任意值如 `px-2.5`、`w-[260px]`）；CSS 只留 @theme token/相位变体/app-region；语义类只留测试锚点（`pet-menu`/`settings-panel`/`speech-bubble(+body)`/`active`/`assistant`）。
- **测试**：前端测试放功能目录下 `__test__/`；Go 测试与源码同目录（Go 忽略 `_` 开头目录，不能用 `__test__/`）。
- **提交**：Conventional Commits、subject 小写开头；当前快速开发阶段直接提交 main。
- **格式**：Prettier（单引号/无分号/无尾逗号/120 宽）；提交前 `pnpm format:check` 必须通过。
- **视觉验收**：视觉类改动先自测（vitest 全绿）再提交；最终视觉验收需用户在真机上对照设计图确认（历史约定：视觉修复不得未经用户确认直接 commit）——Task 7 走查清单是验收入口。
- **临时诊断用完即删**：调试日志定位后必须整体移除。

## 关键决策（执行者先读）

1. **范围**：本计划覆盖 01 气泡、02 输入、03 设置·对话记录、05 形象管理、07 右键菜单。**06 模型与连接 → 另立后续计划**（需要后端 /api/config + provider 热重载 + 密钥存储，属 M3 模型对接子系统）。本计划把设置导航的「模型与连接/外观与动作/关于」保留为禁用占位。
2. **菜单高度算术自洽优先**：设计注释写「约 222（3 形象）/ 单形象 87」。本计划按自洽算术实现：单形象 87、3 形象 228——`menuHeight(n)` 与 JSX 渲染高度必须逐像素一致（这正是本改版要消除的缺陷），与设计的 222 差 6px 是设计稿内部数字不精确所致，以实现自洽为准。
3. **渐变起点色**：设计 07/05 渐变起点 #5CC9A6 与既有 token `--color-primary` #5BC8A6 差 1 个单位，统一用 token（`from-primary`），不再新增近似色。
4. **形象缩略图**：无真实封面图来源，菜单 24px 与形象管理 48px 缩略位统一用「薄荷底+小白人轮廓」占位 SVG（同一 viewBox 复用，两个尺寸）。
5. **导入进度**：后端导入是一次性 POST，无进度通道——设计稿的「62% 进度环/取消」按真实能力降级为**不确定态转圈** + 无取消按钮（导入中行不提供取消）。
6. **拖拽文件夹**：Electron 44 已移除 `File.path`，preload 新增 `getPathForFile`（`webUtils.getPathForFile`）解析拖入的文件/文件夹绝对路径。
7. **跨窗同步**：形象导入/删除发生在设置窗口，桌宠窗口需感知——新增 `notify-models-changed` → 主进程广播 `models-changed` → 桌宠窗口 `loadModels()`（`loadModels` 已内置「当前 modelUrl 不在列表则回退第一个」逻辑，删除当前形象自动回退）。设置窗口自身导入成功后直接本地刷新（store 内已刷新），不需自收广播。
8. **错误行语义**：后端导入失败是原子的（无持久化失败行），诚实映射为「失败行保留直到用户点移除」——petStore 新增 `importName`（尝试导入的源名，成功清除、失败保留供失败行展示），「移除」只清 store 的 importError/importName。
9. **孤儿 token 清理**：气泡/输入条/菜单的投影从 `shadow-mint` 换成各自新 token 后，`shadow-mint`/`shadow-mint-deep` 若无引用在 Task 7 删除（grep 验证）。
10. **导入入口**：菜单不再有导入/删除按钮；占位卡（无模型引导）仍复用 ImportPanel.tsx（URL/zip/dir，不在本计划改版范围）；设置·形象管理页按设计只走文件夹导入（浏览 + 拖放）。

```ts
/** 消息流分组：按本地日分组，标签「今天 10:24」；无 created_at（本地新发）归今天 */
export function groupByDay(items: ChatItem[], now: Date = new Date()): HistoryGroup[] {
  const groups: { day: string; items: ChatItem[] }[] = []
  for (const it of items) {
    const day = dayLabel(it.created_at, now)
    const last = groups[groups.length - 1]
    if (last && last.day === day) last.items.push(it)
    else groups.push({ day, items: [it] })
  }
  return groups.map((g) => ({ label: groupLabel(g.items, now), items: g.items }))
}
```

```ts
export function sessionSubtitle(items: ChatItem[], now: Date = new Date()): string {
```

```tsx
export default function ChatHistoryPage(): ReactElement {

  const clear = useChatStore((s) => s.clear)
  const [query, setQuery] = useState('')
  const [exported, setExported] = useState(false)
  const exportedTimer = useRef<number | null>(null)

  useEffect(() => {
    return () => {
      if (exportedTimer.current !== null) window.clearTimeout(exportedTimer.current)
    }

  const groups = groupByDay(filterChatItems(items, query))

  const doExport = async (): Promise<void> => {
    const { saved } = await window.lovelybuddy.exportFile(exportFileName(new Date()), historyToMarkdown(items))
    if (saved) {
      setExported(true)
      exportedTimer.current = window.setTimeout(() => setExported(false), 2000)
```

```ts
// 菜单尺寸（图 07）：高度随形象数自适应——单一事实来源 menuHeight(n)，
// usePetMenu（扩展量）与 PetMenu（渲染高度/menuTop）都引用它，避免固定高度
// 与渲染内容脱节（旧版 320 固定高度，底部留白会拦截鼠标）。
export const MENU_W = 260

// 菜单贴窗口的内边距
export const MENU_INSET = 4
// 菜单底边与角色头顶的最小间距
const CHAR_GAP = 8

// 内部排版常量（与 PetMenu JSX 的 padding/gap/h-* 精确一致）
export const MENU_PAD = 10 // 菜单四周内边距
export const STATUS_H = 16 // 状态行
export const DIVIDER_H = 1 // 分隔线
export const ROW_H = 40 // 形象行
export const ROW_GAP = 2 // 形象行间距
export const ACTIONS_H = 34 // 底部按钮行
export const SECTION_GAP = 8 // 区段间距（flex gap-2）
export const MAX_LIST_ROWS = 4 // 列表最多可见行数，超出内部滚动

/** 形象列表实际渲染高度（>4 个按 4 行封顶，列表区内部滚动） */
export function listHeight(modelCount: number): number {
  const rows = Math.min(Math.max(modelCount, 0), MAX_LIST_ROWS)
  return rows === 0 ? 0 : rows * ROW_H + (rows - 1) * ROW_GAP
}

/**
 * 菜单总高度：单形象 87（紧凑态，无列表区：10+16+8+1+8+34+10）；
 * 多形象 = 紧凑态 + 列表区 + 两条区段间隙（3 个形象 = 228）。
 */
export function menuHeight(modelCount: number): number {
  if (modelCount <= 1) {
    return MENU_PAD * 2 + STATUS_H + SECTION_GAP * 2 + DIVIDER_H + ACTIONS_H // 87
  }
  return MENU_PAD * 2 + STATUS_H + SECTION_GAP * 4 + DIVIDER_H * 2 + ACTIONS_H + listHeight(modelCount)
}

/** 菜单+内边距的窗口宽度需求（扩展量由主进程按真实 bounds 计算，见 window/bounds） */
export const MENU_REQUIRED_W = MENU_W + MENU_INSET * 2

/** 菜单+内边距+距头顶间隙的窗口绝对高度需求 */
export function menuRequiredHeight(modelCount: number): number {
  return menuHeight(modelCount) + MENU_INSET + CHAR_GAP
}

/**
 * 菜单窗口坐标 top：右贴窗口（right=MENU_INSET），底边距头顶 CHAR_GAP。
 * 头顶窗口坐标 headTop = 窗高 − 模型基准窗高（几何 store 响应式推导）；
 * 窗口被屏幕夹紧导致头顶空间不足时贴窗口顶（菜单压到角色，已知取舍）。
 */
export function menuTop(headTop: number, modelCount: number): number {
  return Math.max(MENU_INSET, headTop - CHAR_GAP - menuHeight(modelCount))
}
```

```tsx
  /** 「聊天」入口（关闭菜单并打开聊天面板，由 App 决定） */

  /** 「设置」入口（关闭菜单并打开设置面板，由 App 决定） */

 * 与 usePetMenu 的扩展量同源（menuLayout 单一事实来源）。

 * 聊天扩展等叠加时窗口左上角远离角色，菜单必须锚角色头顶而不是窗口左上。

 */
export default function PetMenu({ onClose, onChat, onSettings }: Props): ReactElement {
  const models = usePetStore((s) => s.models)
  const modelUrl = usePetStore((s) => s.modelUrl)
  const status = usePetStore((s) => s.status)

    <div

              const active = m.url === modelUrl
              return (
                <button
                  key={m.slug}
                  className={`flex h-10 shrink-0 items-center gap-2 rounded-[10px] px-2 text-left cursor-pointer ${
                    active ? 'active bg-selected-bg font-semibold text-active-ink' : 'bg-transparent text-ink hover:bg-bg'
                  }`}
                  onClick={() => {
                    onClose()
                    selectModel(m)
                  }}
                  title={`${m.name}（${m.kind === 'moc3' ? 'Cubism 4' : 'Cubism 2'}）`}
                >
                  <Thumb />
                  <span className="min-w-0 flex-1 truncate">{m.name}</span>
                  {active && (
                    <svg width="14" height="14" viewBox="0 0 14 14" fill="none" aria-hidden="true">
                      <path

                        strokeWidth="1.6"

            })}
          </div>
          <div className="h-px bg-[#e5dbcc]" />
        </>
      )}
      <div className="flex gap-2">
        <button
          type="button"
          className={`flex h-[34px] flex-1 items-center justify-center gap-1.5 rounded-[10px] text-[11px] font-medium ${
            online
              ? 'bg-linear-to-r from-primary to-deep-end text-white cursor-pointer hover:-translate-y-px active:scale-[0.96]'

          }`}

          onClick={onChat}

            <path d="M1.5 2.5h9v5H4L1.5 10V2.5Z" stroke="currentColor" strokeWidth="1.2" strokeLinejoin="round" />
          </svg>
          聊天
        </button>

          onClick={onSettings}
        >
          <svg width="12" height="12" viewBox="0 0 12 12" fill="none" aria-hidden="true">
```

```go
// dirSize 递归统计形象目录总字节数（WalkDir 求和，读不到的跳过）。
func dirSize(dir string) int64 {
	var n int64
	_ = filepath.WalkDir(dir, func(_ string, d fs.DirEntry, err error) error {
		if err != nil {
			return nil
		}
		if !d.IsDir() {
			if info, err := d.Info(); err == nil {
				n += info.Size()
			}
		}
		return nil
	})
	return n
}

// expressionCount 读取入口 json 的 Expressions 数组长度（Cubism 4 大写 / Cubism 2 小写通用）。
// 读不到/解析失败/无该字段 → 0（前端省略「N 组表情」段）。
func expressionCount(entry string) int {
	b, err := os.ReadFile(entry)
	if err != nil {
		return 0
	}
	var doc struct {
		Expressions []json.RawMessage `json:"Expressions"`
		expressions []json.RawMessage `json:"expressions"`
	}
	if json.Unmarshal(b, &doc) != nil {
		return 0
	}
	if len(doc.Expressions) > 0 {
		return len(doc.Expressions)
	}
	return len(doc.expressions)
}
```

```tsx
function formatBytes(n: number): string {
  return `${(n / 1024 / 1024).toFixed(1)} MB`

/** 行 meta：「hiyori.model3 · 4.2 MB · 3 组表情」（无数据的分段省略） */
function modelMeta(m: AvatarInfo): string {
  const parts = [(m.entry.split('/').pop() ?? m.entry).replace(/\.json$/, '')]
```
